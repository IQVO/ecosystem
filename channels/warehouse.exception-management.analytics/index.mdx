## Overview
  This service's own analytics stream (ADR 0006), written by the SAME
transactional outbox relay as the integration topic: every published
fact appears here too, under the SAME CloudEvents id and `type`, with
only the `dataschema` stream segment different
(urn:warehouse:exception-management:analytics:\<EventName>:v1). It is NOT
an integration contract: the only consumer is this service's
cmd/exceptions-projector (fixed group from `ANALYTICS_CONSUMER_GROUP`,
starting at the earliest retained offset), which folds the events into
the analytical database; its deterministic poison goes to
warehouse.exception-management.analytics.dlq. Other contexts keep
reading warehouse.exception-management.events.
