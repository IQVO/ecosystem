## Overview
  The internal analytics topic (the `AnalyticsTopic` constant in
`internal/adapters/outbound/kafka/analytics_publisher.go`). Carries the
same seven occurrences with the same `type` and payload, but a distinct
`id` per occurrence and dataschema
`urn:warehouse:network-fulfillment:analytics:<EventName>:v<N>` (v1,
except `NetworkOrderAcknowledged` which is v2). There is
no `schema_version` field. Consumed by this service's own analytics
projector (`internal/adapters/inbound/kafka/analytics_consumer.go`),
which handles `NetworkOrderReceived`, `NetworkOrderSubmitted` (claimed,
no report effect), `NetworkOrderAcknowledged` v2, the HISTORIC
`NetworkOrderAcknowledged` v1 still on the topic (unsuffixed type,
published before ADR 0016, counted as before so a replay keeps the
report numbers) and `NetworkOrderRejected`, ignores other types
(`NetworkOrderShipmentConfirmed`, `AcknowledgementDeadlineAtRisk` and
`OrphanedHoldCancelled` today), and dead-letters to
`warehouse.network-fulfillment.analytics.dlq` anything that is not a
valid CloudEvent.
