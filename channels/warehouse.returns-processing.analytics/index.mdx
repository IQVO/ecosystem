## Overview
  This service's own analytics stream (ADR 0007), written by the SAME
transactional outbox pass as the integration topic: every domain event
appears here too, under the SAME CloudEvents id, `type`, `subject` and
key and with a byte-identical payload; only the `dataschema` stream
segment differs
(urn:warehouse:returns-processing:analytics:\<EventName>:v1). It is NOT
an integration contract: the only consumer is this service's
cmd/returns-projector (fixed group from `ANALYTICS_CONSUMER_GROUP`),
which folds five of the seven types into the analytical database (the
two authorization twins are acknowledged and ignored); its
deterministic poison goes to
warehouse.returns-processing.analytics.dlq. Other contexts keep reading
warehouse.returns-processing.events.
