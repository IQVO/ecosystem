## Purpose
A decision-support **customer** of the bounded contexts, not a new domain context: it has no aggregate, no database, publishes no events and subscribes to none. It answers "what needs attention right now" for an LLM host or an operator, and acts as the **console-bff** REST fan-out host for the [warehouse-console](/docs/services/warehouse-console) browser SPA.

| | |
|---|---|
| Repository | [IQVO/warehouse-ops-agent](https://github.com/IQVO/warehouse-ops-agent) |
| DDD classification | Supporting, WES tier (operator tooling, no aggregate) |
| Kafka | none: no produce, no consume |
| Storage | none: stateless |
| Inbound | REST (console, operators); MCP Streamable HTTP at `/mcp`, up to ten read-only tools |
| Writes to other contexts | forbidden; enforced by zero-write architecture tests |

## Three relationships to the fleet
1. **MCP customer.** Reads each context's published MCP server synchronously, per call, with a 10 s timeout (table below). MCP tools are not modelled as catalog messages; they are listed here.
2. **REST fan-out host for console-bff.** `GET /console/orders/{id}/lifecycle` reads four OLTP APIs and `GET /console/reports/wms|wes` reads seven `*-reports` APIs. These calls are the `sends` edges of this service in the diagram.
3. **Telemetry reader.** `GET /runtime-signals` queries Prometheus (Istio request metrics) and Loki (error log lines). Neither is a bounded context.

"core" upstreams are reported as unavailable when they fail; "optional" ones switch the feature off until their `*_MCP_ENDPOINT` is set.

## External systems
- **Anthropic Messages API** (`POST /v1/messages`): only for flow-balance reasoning, when `LLM_MODE` is `shadow` or `on`. The model must answer through a `submit_plan` tool and a deterministic policy layer validates the plan. A circuit breaker falls back to the deterministic decision.
- **Prometheus** and **Loki**: read by `/runtime-signals`.

## Edges that do not exist
Kafka in either direction, network-fulfillment, slotting-optimization, any write call to a sibling, and any Go import of a sibling module.
