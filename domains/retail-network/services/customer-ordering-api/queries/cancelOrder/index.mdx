## Overview
CancelOrder is a request (G12, G25). Every group still PROMISED (no node locked yet) moves to CANCELLATION_REQUESTED and CustomerOrderCancelled is published through the outbox with those groupNos; locked, shipped and delivered groups are untouched. order-sourcing decides: FulfillmentCancelled makes the group CANCELLED (the order is CANCELLED once every group is), FulfillmentCancelRefused returns the group to fulfilment (the vendor ships; the shopper path becomes a return). Refused with 409 cancel-after-lock (ErrCancelAfterLock) when no group is unlocked. Repeating the request, or cancelling a CANCELLED order, returns the order unchanged and publishes nothing.




## POST `(/orders/{orderId}:cancel)`

### Parameters
- **orderId** (path) (required): The customer order id (aggregate root id, CloudEvents subject).
- **Idempotency-Key** (header) (required): Client-chosen key (route, key; 24 hour TTL); a replay with the same body returns the stored response.
