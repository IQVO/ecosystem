## Purpose
Turns a shopper's cart into a customer order: obtains a promise for every shipment group at checkout, records the order with the shopper and ship-to address (synthetic PII, held only here), shows status and tracking, and handles customer cancellation.

## Contract


Event catalog for the **customer-ordering** bounded context of the retail network (commerce tier): it turns a shopper's cart into a customer order, promising and confirming every shipment group at checkout (ADR 0001, ADR 0002).

**Published.** Two integration events, `CustomerOrderPlaced` and `CustomerOrderCancelled`, on `retailnetwork.customer-ordering.events` through a **transactional outbox** (the order row and its already-encoded events are written in ONE database transaction; an always-on relay drains them to Kafka, at-least-once, the CloudEvents `id` is stored with the outbox row). Both types are catalogued in ADR 0004. Nothing is published on `retailnetwork.customer-ordering.analytics`: the model names no analytics-only event for this context. No event carries the ship-to address (PII); `CustomerOrderPlaced` carries the destination postal prefix only.

**Consumed.** Fifteen events from delivery-promise, order-sourcing and shipping-and-tracking (see the `receive` operations and ADR 0003). The messages list only the fields this service relies on; the producers' own AsyncAPI files are authoritative and unknown fields are ignored. Each consumer group name comes from a mandatory environment variable.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka header `content-type: application/cloudevents+json; charset=UTF-8`. `specversion`, `id`, `source` (`/retailnetwork/customer-ordering`), `type`, `subject` (the orderId), `time`, `datacontenttype` (`application/json`) and `dataschema` (`urn:retailnetwork:customer-ordering:events:<EventName>:v1`) are all required. Kafka key = the subject. Type = `com.retailnetwork.commerce.customer-ordering.customerorder.<EventName>`. A breaking payload change is a new `.v2` type, never a mutation. Dispatch on the full `type`, ignore unknown types, dedupe on `id`.

**Conventions.** `data` is camelCase; instants are RFC 3339 UTC; enums are UPPER_SNAKE; optional fields are omitted when absent (never null); arrays are always present.
