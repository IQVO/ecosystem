## Overview
Authorizes one order group's return and publishes `ReturnAuthorized`. The group must be SHIPPED or DELIVERED (`group-not-shipped` otherwise); the lines are resolved against the placed group (`validation-failed` on an unknown lineNo) and the disposition is decided from the read models. A repeat of the same key and body replays the first answer when it was the 201. A refusal that depends on state that can change (`group-not-shipped`, `no-return-destination`, `validation-failed`, `concurrent-update`) is not stored -- the key is released and the same key and body executes again.




## POST `(/return-authorizations)`

### Parameters
- **Idempotency-Key** (header) (required): The fleet idempotency key, 1 to 128 printable ASCII characters. A repeat with the same method, path and body replays the first response with `Idempotency-Replayed` set to true when that response is a success or `authorization-expired`. A refusal that depends on state that can change (`group-not-shipped`, `no-return-destination`, `label-unavailable`, `concurrent-update`, `illegal-transition`, `not-found`, `validation-failed`) and every 5xx is not stored -- the key is released and the same request executes again. The same key on a different request is `409 idempotency-key-reused`.
