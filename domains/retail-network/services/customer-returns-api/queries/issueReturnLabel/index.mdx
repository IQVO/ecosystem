## Overview
Asks the shipping context's `POST /return-labels` route for the reverse label of `packageNo` (1..5), links the tracking number and publishes `ReturnLabelIssued`. The route is the ONE in-org call this context makes; while it is not configured (or answers anything but 200) the answer is `422 label-unavailable` -- tolerant, never a 500. Only an open physical authorization is labelable.




## POST `(/return-authorizations/{authorizationId}/labels)`

### Parameters
- **authorizationId** (path) (required): The return authorization id (`ret-<uuid>`).
- **Idempotency-Key** (header) (required): The fleet idempotency key, 1 to 128 printable ASCII characters. A repeat with the same method, path and body replays the first response with `Idempotency-Replayed` set to true when that response is a success or `authorization-expired`. A refusal that depends on state that can change (`group-not-shipped`, `no-return-destination`, `label-unavailable`, `concurrent-update`, `illegal-transition`, `not-found`, `validation-failed`) and every 5xx is not stored -- the key is released and the same request executes again. The same key on a different request is `409 idempotency-key-reused`.
