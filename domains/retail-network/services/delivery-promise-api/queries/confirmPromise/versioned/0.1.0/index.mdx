## Overview
Called by customer-ordering inside checkout, before the order is placed (E7). PROVISIONAL becomes CONFIRMED and the book hold moves from provisional to confirmed, in one transaction; PromiseConfirmed goes to the analytics topic. Idempotent: confirming an already CONFIRMED promise with the same orderId and groupNo is a no-op returning 200. A hold past holdExpiresAt is refused with promise-hold-expired (409), and a RELEASED or otherwise closed promise with promise-closed (409): checkout then re-quotes and no order is placed.




## POST `(/promises/{promiseId}:confirm)`

### Parameters
- **Idempotency-Key** (header) (required): Client-chosen key; a repeat with the same key and body returns the first result.
- **promiseId** (path) (required): The Promise id.
