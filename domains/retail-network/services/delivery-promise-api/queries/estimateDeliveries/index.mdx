## Overview
A computation over the request body for product listing pages (search results, many items per view). Each item is searched as a single-line group with exactly the quote search of POST /delivery-quotes (the same local read models, OwnerChoice of ADR 0017, netting, scorecard handicap and the SCHEDULED, MEASURED or NOMINAL basis), and each estimate lists the best option per requested tier that a one-line quote would offer, or the OfferConstraint that blocks the tier. The shared inputs are loaded once per request, not per item. The operation is SAFE: it stores nothing (no offer, no outbox event, no hold, no Idempotency-Key row) and an estimate is ADVISORY: it carries no offer id, cannot back POST /promises and never reserves capacity; a quote on the product page or at checkout is what the shopper promises against. An unknown catalogItemId is not an error: it is the ITEM_QUANTITY_NOT_AVAILABLE constraint. The Idempotency-Key is not required and, if sent, it is ignored (a safe request is idempotent by effect, as the guideline treats PUT and DELETE). Makes no synchronous call.




## POST `(/delivery-estimates)`

- **Idempotency-Key** (header): Not required. This operation stores nothing, so a key that is sent is ignored; it is never read, stored or replayed (ADR 0019).
