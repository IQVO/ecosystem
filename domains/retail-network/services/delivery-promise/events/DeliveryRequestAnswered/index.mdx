## Description
`type` = `com.retailnetwork.commerce.delivery-promise.deliveryrequest.DeliveryRequestAnswered`; `dataschema` = `urn:retailnetwork:delivery-promise:analytics:DeliveryRequestAnswered:v1`; subject and key = the requestId, a fresh opaque id minted for the fact. Topic: retailnetwork.delivery-promise.analytics. ANALYTICS ONLY: no integration consumer reads it, only this context's own projector (ADR 0032). One per quote (`POST /delivery-quotes`) or estimate (`POST /delivery-estimates`) answered with HTTP 200, including a request answered with NO feasible promise, which publishes nothing else; a replayed Idempotency-Key and a refused request raise none. BEST EFFORT BY DESIGN: it is raised only while DELIVERY_REQUEST_FACTS_ENABLED is true (default false), after the response was written, from a bounded in-memory queue drained by one background worker that stores one outbox row per fact in its own short transaction; a fact that does not fit the queue or cannot be stored is dropped and counted, never retried, and never changes a response. A coverage share therefore tolerates a bounded loss. No PII: the region is the first two characters of the destination postal prefix, no address and no shopper id.
