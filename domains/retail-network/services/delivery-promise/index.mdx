## Purpose
Tells a shopper, before and at purchase, the date a package will arrive, and makes that date true by construction: a delivery offer is quoted only from a feasible witness path (node cutoff, scheduled departures, delivery wave) that has remaining capacity, and a promise holds that capacity until the order is placed or the hold expires. Judges every promise kept or broken.

## Contract


Event catalog for the **delivery-promise** bounded context of the retail network (commerce tier, Core): it quotes delivery offers from a feasible witness path, holds capacity in PromiseBooks, makes and judges promises (ADR 0002, ADR 0003).

**Published.** Twelve events through a **transactional outbox** (the aggregate rows and the already-encoded events are written in ONE database transaction and an always-on relay drains them to Kafka, at-least-once, the CloudEvents `id` is stored with the outbox row). Six integration events go to `retailnetwork.delivery-promise.events` (PromiseAtRisk, PromiseRevised, PromiseKept, PromiseBroken, PromiseUnkeepable, PromiseBookExhausted); six analytics-only events go ONLY to `retailnetwork.delivery-promise.analytics` (PromiseMade, PromiseConfirmed, PromiseReleased, PromiseCancelled, DeliveryOfferQuoted, PromisePolicyPublished). The types are catalogued in ADR 0004.

**Consumed.** Events of nine producers, kept as event-fed local read models or driving RepromiseOnRisk, JudgeOnDelivery and CancelPromise (ADR 0003). The consumed messages below are a tolerant local copy of the fields this service relies on; the producer's own AsyncAPI is authoritative. Every consumer is idempotent on the CloudEvents `id` (inbox table) and dispatches on the full `type`.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka header `content-type: application/cloudevents+json; charset=UTF-8`. `specversion`, `id`, `source` (`/retailnetwork/delivery-promise`), `type`, `subject` (the aggregate root id), `time`, `datacontenttype` (`application/json`) and `dataschema` (`urn:retailnetwork:delivery-promise:<stream>:<EventName>:v1`) are all required. Kafka key = the subject. Type = `com.retailnetwork.commerce.delivery-promise.<entity>.<EventName>` with entity `promise`, `promisebook`, `deliveryoffer` or `promisepolicy`. A breaking payload change is a new `.v2` type, never a mutation.

**Conventions.** `data` is camelCase; ids are strings; instants are RFC 3339 UTC; optional fields are omitted when unset (never null); arrays are always present.
