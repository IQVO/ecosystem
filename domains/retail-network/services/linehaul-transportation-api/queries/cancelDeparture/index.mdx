## Overview
Moves a SCHEDULED departure to CANCELLED and publishes DepartureCancelled, which delivery-promise and order-sourcing use to re-promise. Every assignment booked on the departure is rebooked onto the next departure from the same origin (BookingMoved) or reported as BookingFailed when none fits. Cancel before cutoffAt wherever possible. Cancelling a CANCELLED departure returns it unchanged.




## POST `(/departures/{departureId}:cancel)`

### Parameters
- **departureId** (path) (required): Departure id.
- **Idempotency-Key** (header) (required): Client-chosen key (1 to 200 printable characters). A repeat of the same request on the same route with the same key within 24 hours returns the first response (status and body, header Idempotency-Replayed: true); a refusal (4xx) is replayed too, a server failure (5xx) is not stored. The same key with another request is 422 idempotency-key-reused.
