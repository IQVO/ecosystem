## Purpose
The authoritative registry of the network's physical shape: every node (vendor fulfillment centres, cross-docks, returns centres, and the network's own sortation centres, delivery stations and air hubs), its declared operational profile, the directed lanes between nodes, the regions, and which delivery station serves which postal area.

Every message is a CloudEvents 1.0 structured-mode JSON document (`application/cloudevents+json`).
`<ctx>.events` topics carry the integration contract; `<ctx>.analytics` topics carry projector input for the
context's own reports and are never consumed by another context.

## Contract


Event catalog for the **node-topology** bounded context of the retail
network (logistics tier): the authoritative registry of nodes, their
declared operational profiles, the directed lanes between them, the regions
and which delivery station serves which postal prefix (ADR 0001, ADR 0002).

**Published.** Nine events, all on the topic `retailnetwork.node-topology.events`,
through a **transactional outbox**: the aggregate row and its already-encoded
events are written in ONE database transaction and an always-on relay drains
them to Kafka (at-least-once; the CloudEvents `id` is stored with the outbox
row, so a retry republishes the same `id`). The nine types are catalogued in
ADR 0004.

**Consumed.** None (ADR 0003). The context consumes no Kafka topic and calls
no sibling context.

**Analytics.** The model names no analytics-only event for this context, so
nothing is published on `retailnetwork.node-topology.analytics`.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka
header `content-type: application/cloudevents+json; charset=UTF-8`.
`specversion`, `id`, `source` (`/retailnetwork/node-topology`), `type`,
`subject` (the aggregate root id), `time`, `datacontenttype`
(`application/json`) and `dataschema`
(`urn:retailnetwork:node-topology:events:<EventName>:v1`) are all required.
Kafka key = the subject, so one aggregate's events stay ordered on one
partition. Type = `com.retailnetwork.logistics.node-topology.<entity>.<EventName>`
with entity `node`, `lane`, `servicearea` or `region`. A breaking payload
change is a new `.v2` type, never a mutation. Dispatch on the full `type`,
ignore unknown types, dedupe on `id`.

**Conventions.** `data` is camelCase; timestamps are RFC 3339 UTC; local
times are `HH:mm` in the declared `timezone`; optional fields are omitted
when unset except where a message says a field is `null`.
