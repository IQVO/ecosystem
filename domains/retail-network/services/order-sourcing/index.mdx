## Purpose
Decides, as late as the promise allows, which node and path will actually fulfil each shipment group. Keeps assignments in a virtual queue, re-optimises them against current capacity and cost until the release point, sends the group to the node, reassigns on rejection or expiry, and locks the assignment once the node commits.

## Contract


Event catalog for the **order-sourcing** bounded context of the retail network (commerce tier): it decides which vendor node and path fulfil each shipment group (ADR 0001, ADR 0002).

**Published.** Ten events of the FulfillmentAssignment aggregate (entity `assignment`): eight on `retailnetwork.order-sourcing.events` and the two analytics-only ones (FulfillmentQueued, FulfillmentDelivered) ONLY on `retailnetwork.order-sourcing.analytics`, through a **transactional outbox**: the aggregate row and its already-encoded events are written in ONE database transaction and an always-on relay drains them to Kafka (at-least-once; the CloudEvents `id` is stored with the outbox row, so a retry republishes the same `id`). The ten types are catalogued in ADR 0004.

**Consumed.** Thirty-two event types from nine producers (ADR 0003): commands that drive the aggregate (CustomerOrderPlaced, CustomerOrderCancelled, PromiseRevised, the purchase-order outcomes, VendorShipmentConfirmed, PackageDelivered, BookingMoved) and the events that feed the five local read models (NodeProfileView, NetworkGraphView, AvailabilityView, ScorecardView, PromiseBookPressureView). Every consumer is idempotent on the CloudEvents `id` and dispatches on the full `type`; unknown types and fields are ignored.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka header `content-type: application/cloudevents+json; charset=UTF-8`. `specversion`, `id`, `source` (`/retailnetwork/order-sourcing`), `type`, `subject` (the assignmentId), `time`, `datacontenttype` (`application/json`) and `dataschema` (`urn:retailnetwork:order-sourcing:<stream>:<EventName>:v1`) are all required. Kafka key = the subject. Type = `com.retailnetwork.commerce.order-sourcing.assignment.<EventName>`. A breaking payload change is a new `.v2` type, never a mutation.

**Conventions.** `data` is camelCase; timestamps are RFC 3339 UTC; optional fields are omitted when unset; arrays are always present.
