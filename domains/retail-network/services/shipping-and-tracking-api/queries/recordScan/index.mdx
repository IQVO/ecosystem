## Overview
RecordScan over REST. Scans apply in time order; an older scan is stored but does not move the state (409 scan-out-of-order, the scan is kept with applied=false). A scan whose scanType has no edge from the current state is stored with applied=false and answers 409 illegal-transition. A known scanId answers 409 duplicate-scan and stores nothing. A closed journey answers 409 journey-closed.




## POST `(/journeys/{trackingNumber}/scans)`

### Parameters
- **trackingNumber** (path) (required)
- **Idempotency-Key** (header) (required): Client-chosen key (at most 128 characters); a repeat with the same key replays the first response (24 hours).
