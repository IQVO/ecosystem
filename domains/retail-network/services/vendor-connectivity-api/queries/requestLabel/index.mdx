## Overview
Synchronous (the documented exception to the `202` rule, G31): labels are issued by
shipping-and-tracking (`POST /labels`, `IssueLabel`, called with `poNumber`,
`packageNo`, `assignmentId`, `orderId` and `tier` that this context holds from
the release) inside this request and returned in the response. Allowed only
once the purchase order is `ACCEPTED` (`ErrLabelBeforeAcceptance`). A label
never carries the ship-to address. Re-requesting a label for the same
`(poNumber, packageNo)` returns the label already issued. When
shipping-and-tracking cannot answer, the answer is `503` `upstream-unavailable`;
labels already issued stay stored and a retry returns them.





## POST `(/vendor/shipping-labels)`

### Parameters
- **Idempotency-Key** (header) (required): Client-chosen key. A retry with the same key returns the first response (for an asynchronous write, the same `transactionId`).
