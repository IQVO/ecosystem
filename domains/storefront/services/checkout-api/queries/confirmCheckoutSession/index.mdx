## Overview
ConfirmSession with the PSP payment method token (never a card number). AUTHORIZING calls customer-payments POST /payment-authorizations (key `<sessionId>:auth:<attempt>`, the attempt counter grows on every retry after a decline; allocations per group); the authorized amount must equal the quote total (ErrAuthorizationMismatch). PLACING persists the placement request and calls customer-ordering POST /checkout with Idempotency-Key equal to the sessionId. Outcomes: 200 with the session in a definitive state (COMPLETED, DECLINED, REQUOTE_REQUIRED with requotedOffers after a successful void, or FAILED after a void plus an alert for a contract bug); 202 while the place-order outcome is unknown (the session stays PLACING; poll GET /checkout-sessions/\{sessionId\}). A DECLINED session may be confirmed again with another token while the price quote is valid.




## POST `(/checkout-sessions/{sessionId}/confirmations)`

### Parameters
- **sessionId** (path) (required)
- **Idempotency-Key** (header) (required): Client-generated UUID per logical submit, 1-128 printable ASCII characters. A repeat of the same method, path and body replays the stored answer (response header Idempotency-Replayed: true); the same key on a different request is 409 idempotency-key-reused.
