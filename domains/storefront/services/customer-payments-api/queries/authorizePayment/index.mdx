## Overview
AuthorizePayment. One authorization per checkout session (ErrDuplicateAuthorization; a replay with the same Idempotency-Key returns the existing one). checkout calls this with key &lt;sessionId>:auth and one allocation per shipment group; allocations must sum to the authorized total and name the session's groups (ErrAllocationMismatch). On a provider decline the record is DECLINED (terminal) and the checkout session stays open for another token.




## POST `(/payment-authorizations)`

### Parameters
- **Idempotency-Key** (header) (required): Client-generated UUID per logical submit (1 to 128 printable ASCII characters); a retry reuses it. The same key with the same request (method, path, body) replays the stored answer with Idempotency-Replayed: true; the same key with another request is 409 idempotency-key-reused. Missing is 400 idempotency-key-required, not 1 to 128 printable ASCII characters is 400 idempotency-key-invalid.
