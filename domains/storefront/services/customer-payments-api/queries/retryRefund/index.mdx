## Overview
RetryRefund, the ops route; no request body. Moves a FAILED refund back to REQUESTED and tries the provider once more, at most 5 attempts in all. The answer is 200 with the Refund as it stands after that attempt (SUCCEEDED, FAILED again with failureCode, or still REQUESTED when the provider is unreachable); it is never 503. A refund that is not FAILED, or whose attempts are used up, is 409 illegal-transition.




## POST `(/refunds/{refundId}/retries)`

### Parameters
- **refundId** (path) (required)
- **Idempotency-Key** (header) (required): Client-generated UUID per logical submit (1 to 128 printable ASCII characters); a retry reuses it. The same key with the same request (method, path, body) replays the stored answer with Idempotency-Replayed: true; the same key with another request is 409 idempotency-key-reused. Missing is 400 idempotency-key-required, not 1 to 128 printable ASCII characters is 400 idempotency-key-invalid.
