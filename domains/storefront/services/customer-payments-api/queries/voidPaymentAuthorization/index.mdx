## Overview
VoidAuthorization. checkout calls this with key &lt;sessionId>:void, and only after a definitive rejection of the place-order step (never while the outcome is in doubt; that side is guarded by checkout's ErrPlacementInDoubt). VoidUnboundAuthorizations also voids an authorization that no CheckoutCompleted bound within 24 h.




## POST `(/payment-authorizations/{authorizationId}/voids)`

### Parameters
- **authorizationId** (path) (required)
- **Idempotency-Key** (header) (required): Client-generated UUID per logical submit (1 to 128 printable ASCII characters); a retry reuses it. The same key with the same request (method, path, body) replays the stored answer with Idempotency-Replayed: true; the same key with another request is 409 idempotency-key-reused. Missing is 400 idempotency-key-required, not 1 to 128 printable ASCII characters is 400 idempotency-key-invalid.
