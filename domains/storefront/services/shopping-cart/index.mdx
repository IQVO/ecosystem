## Purpose
Holds a shopper's intent: cart lines, the destination postal prefix, the delivery quote delivery-promise returned for the cart (per shipment group, with its offers and expiry), the shopper's tier selection per group, and a labelled, non-binding estimate (effective prices + selected tier charges + tax band) so the total cost is visible up front.

context's own reports and are never consumed by another context.

## Contract


Event catalog for the **shopping-cart** bounded context of the storefront (Supporting subdomain): a shopper's held intent, the delivery quote and selections, and the labelled non-binding estimate (ADR 0001, ADR 0002).

**Published.** Four events on `retailnetwork.shopping-cart.analytics`, all analytics-only (decision H1: removal, quantity changes and merge raise none): `CartLineAdded`, `CartDeliveryQuoted`, `CartAbandoned`, `CartCheckedOut`. They go through a **transactional outbox**; an always-on relay drains them to Kafka, at-least-once. The types are catalogued in ADR 0004.

**Consumed.** `CatalogItemCreated`, `CatalogItemDiscontinued` (offer-availability); `ItemPriceChanged`, `ItemPriceWithdrawn`, `DeliveryChargeScheduleChanged`, `TaxTableChanged` (pricing); `CheckoutCompleted` (checkout). They feed the local read models PurchasabilityView and EstimateView and run the policy CloseOnCheckoutCompleted. The messages list only the fields this service relies on; the producer's own AsyncAPI file is authoritative and unknown fields are ignored. Consumer group names come from mandatory environment variables.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka header `content-type: application/cloudevents+json; charset=UTF-8`. `specversion`, `id`, `source` (`/retailnetwork/shopping-cart`), `type`, `subject` (the cartId), `time`, `datacontenttype` (`application/json`) and `dataschema` (`urn:retailnetwork:shopping-cart:analytics:<EventName>:v1`) are all required. Kafka key = the subject. Type = `com.retailnetwork.storefront.shopping-cart.cart.<EventName>`. A breaking payload change is a new `.v2` type, never a mutation. Dispatch on the full `type`, ignore unknown types, dedupe on `id`.

**Conventions.** `data` is camelCase; instants are RFC 3339 UTC; enums are UPPER_SNAKE.
