## Overview
`from_handoff_point_id` and `to_handoff_point_id` are handoff points of the fleet's map (AS/RS ports, stations). The leg is QUEUED until a robot is assigned (`LegAssigned`), then the robot picks the container at `from` (`ContainerPickedUp`) and drops it at `to` (`LegCompleted`), or the leg ends `LegFailed` with a reason. A leg is refused at once when the container already has an open leg (`422 container-busy`), a handoff point is unknown (`422 unknown-handoff-point`), no route joins them (`422 handoff-unreachable`) or no robot is online (`422 fleet-unavailable`). `reference` is echoed in every event of the leg.





## POST `(/fleets/{fleetId}/legs)`

### Parameters
- **fleetId** (path) (required): The fleet id (the map file's `fleetId`, e.g. AMR1).
- **Idempotency-Key** (header) (required): Caller-minted key, 1 to 128 characters (fleet guideline R3-R5); a missing or longer one is `400 idempotency-key-required`.
