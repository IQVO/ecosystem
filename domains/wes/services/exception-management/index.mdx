## Contract


Event catalog for the **exception-management** bounded context (WES
subdomain): the Problem Solve lifecycle (ADR 0001, ADR 0002). Every case
is opened by a fact another context published; this service owns the
triage, assignment, SLA and resolution of that case, never the producer's
own state.

**Published.** The `ExceptionCase` aggregate raises six events and the
`ExceptionPolicy` aggregate one, all published to
`warehouse.exception-management.events` through a **transactional
outbox**: the aggregate row and its already-encoded events are written in
ONE database transaction and a relay drains them to Kafka (at-least-once;
the CloudEvents `id` is stored with the outbox row, so a retry republishes
the same `id`). Kafka key = case id (source type for the policy event), so
one case's history stays ordered on one partition.

**Consumed (ADR 0003).** Exception facts from six sibling contexts:
fulfillment-execution (`TaskCPTMissed`, `PackageDiverted`,
`WeightDiscrepancyDetected`), wes-work-planning
(`BacklogThresholdBreached`), network-fulfillment
(`AcknowledgementDeadlineAtRisk`, `OrphanedHoldCancelled`),
order-management (`OrderRepromised`, correlation for auto-resolve only),
returns-processing (`UnexpectedReturnReceived`) and inventory-storage
(`DiscrepancyDetected`, `ItemUnlocated`). Each consumed message opens or
touches exactly one open case per dedup key (source type, source subject,
site); the source payload is frozen on the case, never re-fetched. The
consumed messages below are the producers' own contracts, restated here
and never imported.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka
header `content-type: application/cloudevents+json; charset=UTF-8`.
`specversion`, `id`, `source` (`/warehouse/exception-management`), `type`,
`subject` (the case id; the source type for the policy event), `time`,
`datacontenttype` (`application/json`) and `dataschema`
(`urn:warehouse:exception-management:events:<EventName>:v1`) are all
required. Kafka key = the subject. Type =
`com.warehouse.wes.exception-management.<entity>.<EventName>`. A breaking
payload change is a new `.v2` type, never a mutation.
