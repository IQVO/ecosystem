## Overview
Returns `200 {"status":"ready"}` while the service is ready to accept new traffic, and `503 {"status":"not_ready"}` once graceful shutdown has begun (ADR-0029) — the readiness gate is flipped as the FIRST step of shutdown, before the HTTP server stops accepting connections, so a Kubernetes readinessProbe pointed here has a window to stop routing new traffic before the listener closes. With `PATH_CATALOGUE_SOURCE=kafka` it also returns `503` from boot until the process-path catalogue replay has caught up: the listener starts before the replay so `/healthz` answers at once (ADR-0044). Distinct from `/healthz` (liveness, never flipped by shutdown).
