## Overview
The Pack-path counterpart to `complete`: the station holding the active claim on a Pack task scans the order's contents and seals them into a brand-new Package resource (created by this call, not pre-existing — see the `Location` header). The task itself is left claimed; a separate `POST /tasks/{id}/complete` call finishes the Pack task once the package is sealed. Requires at least one scanned item — an empty `contents` array is a domain invariant violation (`422`), not a malformed request (`400`), since the array is present and well-formed, just semantically insufficient to seal.





## POST `(/tasks/{id}/seal-package)`

### Parameters
- **id** (path) (required): The Pack task id whose active claim authorizes this seal.
