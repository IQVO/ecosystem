## Purpose
Pick, pack and SLAM task lifecycle with pull-based claimNext dispatch and lease semantics. The execution side of the WES: work is claimed by stations and associates, never pushed.

| | |
|---|---|
| Bounded context | `fulfillment-execution` |
| Domain | WES (`wes`) |
| DDD classification | Core |
| Tier | WES |
| Publishes (Kafka) | `warehouse.fulfillment.events`<br/>`warehouse.fulfillment.analytics` |
| Consumes (Kafka) | `warehouse.work-planning.events`<br/>`warehouse.process-path-management.events`<br/>`warehouse.product-master.events` |
| CloudEvents type prefix | `com.warehouse.wes.fulfillment-execution.` |
| Event source | `/warehouse/fulfillment-execution` |
| Repository | [IQVO/fulfillment-execution](https://github.com/IQVO/fulfillment-execution) |
| REST API | [fulfillment-execution-api](/docs/services/fulfillment-execution-api) |

Every message is a CloudEvents 1.0 structured-mode JSON document (`application/cloudevents+json`).
`<ctx>.events` topics carry the integration contract; `<ctx>.analytics` topics carry projector input for the
context's own reports and are never consumed by another context.

## Contract


Kafka events produced and consumed by the **Fulfillment Execution** bounded context (WES subdomain).

Every message — integration topic and analytics topic alike — is a **CloudEvents 1.0** event in the Kafka protocol binding's *structured* content mode (ADR-0032): the Kafka message value is the JSON event, and every message carries the Kafka header `content-type: application/cloudevents+json; charset=UTF-8` plus W3C `traceparent`/`tracestate`. There is no other envelope.

Required attributes: `specversion` (`1.0`), `id` (UUID v4, stable across outbox redelivery; the consumer idempotency key), `source` (`/warehouse/fulfillment-execution` for this service), `type` (`com.warehouse.<subdomain>.<bounded-context>.<entity>.<EventName>`), `subject` (aggregate id, equal to the Kafka key), `time` (occurred-at, UTC), `datacontenttype` (`application/json`) and `dataschema` (`urn:warehouse:<repo>:<events|analytics>:<EventName>:v<N>`). `data` uses snake_case keys.

The same `type` names an occurrence on both the integration and analytics topics; `dataschema` names the payload shape. A breaking payload change ships as a new `.v2` type with a new dataschema version.
