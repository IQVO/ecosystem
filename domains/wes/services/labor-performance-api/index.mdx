## Purpose
Engineered labor standards and actual-versus-standard performance scoring. Observes task completion from fulfillment-execution; it never drives work.

| | |
|---|---|
| Bounded context | `labor-performance` |
| Domain | WES (`wes`) |
| DDD classification | Supporting |
| Tier | WES, downstream observer |
| Repository | [IQVO/labor-performance](https://github.com/IQVO/labor-performance) |
| Events | [labor-performance](/docs/services/labor-performance) |

This service groups the context's synchronous surface: the OLTP REST API (`openapi.yaml`) and, where the
context has one, the separate read-only reports API (`openapi-reports.yaml`) served by its `*-reports`
binary from an isolated analytical database. Endpoints are unauthenticated fleet-wide.


Engineered labor standards (expected time per TaskType) and actual-vs-standard performance scoring for completed fulfillment-execution tasks. This service defines standards and reads performance/scorecards; it NEVER accepts a TaskPerformance write over REST — that is exclusively driven by the inbound Kafka consumer of fulfillment-execution's TaskCompleted event (see apis/asyncapi.yaml).
