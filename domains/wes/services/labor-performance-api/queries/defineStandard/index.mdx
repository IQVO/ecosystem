## Overview
If a standard is already active for this TaskType, it is closed (its effective range ends now) and a new one starts — append-only history, never an in-place overwrite.

Idempotent retries: clients MUST always send a non-empty `Idempotency-Key` header (any unique value per logical request) when the Postgres backing is configured; a retried request with the same key and body replays the original response byte-for-byte instead of defining the standard a second time.





## POST `(/standards)`

### Parameters
- **Idempotency-Key** (header): A caller-minted unique key per logical request (e.g. a UUID). Clients must always send a non-empty key on POST /standards: with the Postgres backing configured, a retry carrying the same key and an identical body replays the original stored response instead of re-executing the create; the same key with a different body is rejected with 422 idempotency-key-reused. Declared required: false because the in-memory configuration accepts the request without a key (no transactional backing to gate on) — never rely on that in a real deployment.
