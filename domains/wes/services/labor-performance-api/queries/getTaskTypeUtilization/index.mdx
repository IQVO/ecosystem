## Overview
Measured task time vs. measured idle time (between-task waits that already ended) for one TaskType. The still-running open gap of someone idle right now is NOT included at this scope: openGapSeconds is always 0 here, and the open gap is computed per associate only (see /associates/\{associateId\}/utilization). Always returns 200, including a zero-count result for a TaskType this service has never observed.





## GET `(/task-types/{taskType}/utilization)`

### Parameters
- **taskType** (path) (required)
- **window** (query): A Go duration string (e.g. "1h", "30m") for the trailing window to measure over. Defaults to 1 hour when omitted or malformed.





### Responses

#### <span className="text-green-500">200 OK</span>
Idle-gap / utilization read model for either one TaskType (fleet-wide) or one associate, over a trailing window. taskType and associateId are mutually exclusive -- whichever endpoint served the request populates its own identifying field and omits the other.
