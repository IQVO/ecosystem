## Description
The SAME domain event as the analytics stream's LaborStandardDefined message, with the SAME `data` (field names and types unchanged), on the integration topic and with the `:events:` dataschema. Subject is the standard id; the partition key is the TaskType, so every revision of one task type stays in order. A consumer (e.g. warehouse-planning, which keeps a local copy of the standards) treats the optional fields as optional: messages produced before an additive field existed simply do not carry it.
