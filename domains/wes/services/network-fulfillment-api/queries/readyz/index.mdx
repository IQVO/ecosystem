## Overview
Readiness, separate from liveness (`/healthz`, above): reports `ready` until graceful shutdown begins, at which point it flips to `not_ready` as the FIRST step of the shutdown sequence (ADR 0004) -- before the HTTP server stops accepting connections -- so a Kubernetes `readinessProbe` pointed here gets a window to stop routing new traffic before the drain that follows. `/healthz` stays a pure liveness signal and is never flipped by this.
