## Description
Raised when `ReconcileSubmittedOrders` settles the order `SUBMITTED -> ACKNOWLEDGED` (ADR 0016). `receivedAt` is carried so consumers can compute acknowledgement latency (`at - receivedAt`) without a second lookup — the analytics projection does exactly that. Consumed by the analytics projector.

**Versioning.** This is the v2 type; the meaning of the unsuffixed v1 type changed (it was published at `SUBMITTED`, before reconciliation), which the fleet CloudEvents standard treats as breaking. The v1 type `com.warehouse.wes.network-fulfillment.networkorder.NetworkOrderAcknowledged` (dataschema `...:analytics:NetworkOrderAcknowledged:v1`) is no longer published but messages already on the topic stay, and the projector still handles them as before (v1 counted once, with the same latency).

`type`: `com.warehouse.wes.network-fulfillment.networkorder.NetworkOrderAcknowledged.v2` — `dataschema`: `urn:warehouse:network-fulfillment:analytics:NetworkOrderAcknowledged:v2`.
