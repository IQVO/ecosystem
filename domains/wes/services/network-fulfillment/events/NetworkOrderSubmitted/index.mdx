## Description
Raised by the `NetworkOrder` aggregate in the same atomic scope that moves the order to `SUBMITTED` (ADR 0016): the decision to accept in full has been taken, the network has been told yes and a held order exists in order-management (`localOrderId`), but the submission is only accepted-for-processing and NOT yet reconciled against the network's transaction-status record (ADR 0001 §5). It is exactly what `NetworkOrderAcknowledged` v1 used to announce. A consumer must not treat it as a settled commitment: the settle is `NetworkOrderAcknowledged` (v2); a refused submission is `NetworkOrderRejected` with `reason=SUBMISSION_FAILED`.

`type`: `com.warehouse.wes.network-fulfillment.networkorder.NetworkOrderSubmitted` — `dataschema`: `urn:warehouse:network-fulfillment:events:NetworkOrderSubmitted:v1`.
