## Description
Raised by `SweepOrphanedHolds` (ADR 0024) once per hold it frees: the order-management order raised for this demand was still held after `acknowledgeBy` plus `ORPHAN_HOLD_GRACE`, the `NetworkOrder` was never committed to (still `NEW`, or `REJECTED` with the cancel never confirmed), and order-management confirmed the hold is gone. The sweep NEVER changes the order's state — `RejectOverdueOrders` owns that and publishes `NetworkOrderRejected` — and it raises this event only when the hold was actually freed: a hold order-management reports as already released (409/422) was not an orphan and raises nothing. The outcome is recorded in the same transaction as the event, so it fires once per hold and is not re-raised on later passes.

`answer` is what order-management said to the cancel: `CANCELLED` (2xx) or `NOT_FOUND` (404, the hold no longer existed — still done). `localOrderId` is the order-management order that was held; it is published here and nowhere else for an order that was never submitted, because `GET /network-orders/{networkRef}` exposes `localOrderId` only from `SUBMITTED` on.

`type`: `com.warehouse.wes.network-fulfillment.networkorder.OrphanedHoldCancelled` — `dataschema`: `urn:warehouse:network-fulfillment:events:OrphanedHoldCancelled:v1`.
