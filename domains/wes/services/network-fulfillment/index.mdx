## Purpose
Anti-corruption layer between the fleet and an external retail fulfillment network (Amazon Selling Partner API): network-originated demand, the acknowledgement clock and capacity-aware advertised availability.

|---|---|
| Bounded context | `network-fulfillment` |
| Domain | WES (`wes`) |
| DDD classification | Supporting |
| Tier | WES, external network edge (anti-corruption layer) |
| Publishes (Kafka) | `warehouse.network-fulfillment.events`<br/>`warehouse.network-fulfillment.analytics` |
| Consumes (Kafka) | nothing: this context is a pure publisher |
| CloudEvents type prefix | `com.warehouse.wes.network-fulfillment.` |

Every message is a CloudEvents 1.0 structured-mode JSON document (`application/cloudevents+json`).
`<ctx>.events` topics carry the integration contract; `<ctx>.analytics` topics carry projector input for the
context's own reports and are never consumed by another context.

## Contract


Domain-event catalog for **Network Fulfillment**, a Supporting bounded
context in the WES (Warehouse Execution Systems) subdomain: the
anti-corruption layer between the warehouse-systems fleet and an
external retail fulfillment network. One aggregate raises every event
documented here:

- `NetworkOrder` (package `internal/domain/networkorder`) — one network
  purchase order and its acknowledgement lifecycle. Raises
  `NetworkOrderReceived`, `NetworkOrderSubmitted`,
  `NetworkOrderAcknowledged` (v2: raised when the order settles
  `ACKNOWLEDGED`, ADR 0016), `NetworkOrderRejected`,
  `NetworkOrderShipmentConfirmed` and (from the
  acknowledgement sweep, without a state transition)
  `AcknowledgementDeadlineAtRisk`; and (from the orphaned-hold sweep,
  ADR 0024, also without a state transition) `OrphanedHoldCancelled`.

**Envelope (mandatory, ADR 0008).** Every message on every channel of
this service is a CloudEvents 1.0 event in *structured content mode*
(Kafka protocol binding): the Kafka message value is the JSON event
format, content type `application/cloudevents+json`, and every message
carries the Kafka header
`content-type: application/cloudevents+json; charset=UTF-8`. There is no
other envelope. All of `specversion`, `id`, `source`, `type`, `subject`,
`time`, `datacontenttype` and `dataschema` are REQUIRED. W3C trace
context, when present, travels in Kafka headers, never as extension
attributes: an event written through the transactional outbox inside a
span carries that span's `traceparent` (and `tracestate` / `baggage`
when present), stored with the outbox row and sent by the relay
(ADR 0022). Consumers may extract these headers and must not require
them. The Kafka message key is the network order reference
(`networkRef`, identical to `subject`), so every event for one order
lands on the same partition.

**Type naming.** `type` is
`com.warehouse.<subdomain>.<bounded-context>.<entity>.<EventName>`. For
this context the subdomain is `wes`, the bounded context is
`network-fulfillment` and the entity is `networkorder`, e.g.
`com.warehouse.wes.network-fulfillment.networkorder.NetworkOrderReceived`.
The SAME `type` is used for the occurrence on the integration and on
the analytics channel; `dataschema`
(`urn:warehouse:network-fulfillment:<events|analytics>:<EventName>:v<N>`)
names the payload shape. A breaking change gets a new `.v2`
type and a new dataschema version, never a mutation of these:
`NetworkOrderAcknowledged` changed meaning in ADR 0016 and is published
as `...networkorder.NetworkOrderAcknowledged.v2` /
`...:NetworkOrderAcknowledged:v2`.

**Consumers** must dispatch on the full `type`, ignore unknown types,
dedupe on `id` (stable across outbox redelivery), and dead-letter or
skip — never parse as a legacy shape — anything that fails CloudEvents
validation.
