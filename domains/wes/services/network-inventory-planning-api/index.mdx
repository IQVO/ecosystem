## Purpose
SKU placement, inventory balancing and inter-warehouse transfer orchestration: advisory transfer proposals and an operator-approved transfer saga. Fails closed when its local facts are empty or stale.

| | |
|---|---|
| Bounded context | `network-inventory-planning` |
| Domain | WES (`wes`) |
| DDD classification | Core |
| Tier | WES, inter-warehouse transfer planning |
| Repository | [IQVO/network-inventory-planning](https://github.com/IQVO/network-inventory-planning) |
| Events | [network-inventory-planning](/docs/services/network-inventory-planning) |

This service groups the context's synchronous surface: the OLTP REST API (`openapi.yaml`) and, where the
context has one, the separate read-only reports API (`openapi-reports.yaml`) served by its `*-reports`
binary from an isolated analytical database. Endpoints are unauthenticated fleet-wide.


Advisory network inventory balancing for the warehouse-systems fleet.

Network Inventory Planning projects sibling-context facts (site capability,
site-SKU demand, published capacity) into local read models and proposes
inter-warehouse transfers. It never mutates physical stock: approval,
reservation and physical execution live in their owning contexts.
