## Overview
Takes a proposal snapshot (origin, destination, SKU, quantity, policy
version) and validates it against the CURRENT fail-closed read
models. On success the InterWarehouseTransfer saga persists through
PROPOSED → APPROVED → ALLOCATING and, in the same transaction,
enqueue TransferPlanApproved and TransferAllocationRequested into the
transactional outbox; a relay publishes them to Kafka and
inventory-storage's reply later drives the transfer to ALLOCATED or
UNFULFILLABLE. Idempotent per the required Idempotency-Key header:
replaying the same key with the same payload returns the ORIGINAL
transfer (replayed: true); the same key with a different payload is a
409. Fail-closed validation failures (missing/stale/disabled facts)
return 422; unusable read models return 503.





## POST `(/v1/transfers:approve)`

### Parameters
- **Idempotency-Key** (header) (required): Transfer-level idempotency key; a fresh key per logical approval.
Replaying a key replays the FIRST transfer it created.
