## Overview
The CancelOrder use case. Revokes every allocated line's reservation on inventory-storage via `DELETE /reservations/{id}`, then cancels every line. Publishes `OrderCancelled`.

**BR6 — the cancellation boundary:** this is legal ONLY while no line has reached `Released`. The boundary is checked BEFORE any reservation is revoked, so a rejected cancellation leaves inventory-storage completely untouched. Once any line is released, v1 does NOT claw back the released work — a deliberate, documented gap (see ADR 0004), not an oversight.

A failed revoke fails the whole cancellation and leaves the order untouched, so retrying is safe.
