## Overview
Reads order-management's LOCAL read model of warehouse-planning's CapacityPlans for one site (ADR 0031): a PLANNED statement about a future window — the demand the planned capacity cannot process in it (`shortage`, in orders) — mirrored from the CloudEvents warehouse-planning publishes on `warehouse.warehouse-planning.events`. It is not live execution state and is never refreshed by calling warehouse-planning. Windows of every `status` are listed (a `DRAFT` is visible here but never influences an order; only a `PUBLISHED` plan with `shortage > 0` annotates orders — see `capacityConstraint` on the Order schema). Windows that ended before `from` are omitted. This route exists only when the integration is enabled; otherwise it is a 404.





## GET `(/planned-capacity)`

### Parameters
- **site** (query) (required): The planning `location` — a site/building code such as `SIM1` (exact, case-sensitive match).

- **from** (query): RFC 3339 instant; only windows whose end is after it are listed. Defaults to now.
