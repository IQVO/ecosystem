## Overview
Returns 200 `{"status":"ready"}` while the process accepts traffic and 503 `{"status":"not_ready"}` once graceful shutdown has begun (ADR 0025): the readiness gate is flipped first, before the HTTP server or any consumer is stopped, so a Kubernetes readinessProbe can drain traffic during `SHUTDOWN_DRAIN_DELAY`. Like `/healthz` it does not check downstream dependencies; unlike `/healthz` it is the one that changes during shutdown.
