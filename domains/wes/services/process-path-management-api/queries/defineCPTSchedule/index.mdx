## Overview
There is no separate create/revise endpoint: every PUT replaces the schedule's timezone and cutoffs in full (ADR 0010) — a CPTSchedule has no partial-update semantics. Invariants: at least one cutoff; cptIds unique within the schedule; every cutoff's eligiblePathIds entry must reference an Active ProcessPath in this service's own store (the one cross-aggregate check, enforced at write time). A no-op revision (identical timezone and cutoffs) is a successful 200 that does NOT republish CPTScheduleChanged.
