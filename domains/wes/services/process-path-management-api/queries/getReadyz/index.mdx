## Overview
Distinct from liveness (GET /healthz). Ready means: the service is not draining AND Postgres answers a ping AND a Kafka broker answers a metadata request (reachability only; topics are never required). The dependency verdict is cached for a few seconds. Readiness flips to not-ready as the FIRST step of a graceful shutdown drain (503 with a status body), so a Kubernetes readinessProbe stops routing new traffic while in-flight requests finish. Liveness never flips.
