## Overview
Returns only ACTIVE flows by default; pass ?all=true for the audit view (ACTIVE and RETIRED). The list is keyset-paginated (REST guideline section 3): `limit` (1-500, default 100) and an opaque `cursor`, in flowId order (the unique key); the answer is `{items, nextCursor}` and `nextCursor` is absent on the last page. Filters (`all`) are repeated on every page request. Any query parameter other than `all`, `limit` and `cursor` is 400 `unknown-query-parameter`.





## GET `(/process-flows)`

### Parameters
- **all** (query): When true, includes RETIRED flows too.
- **limit** (query): Page size of a collection GET (REST guideline 3.2): an integer from 1 to 500, default 100. Anything else is 400 `invalid-limit`.
- **cursor** (query): Opaque page token: the previous page's `nextCursor`, passed back unchanged together with the same filters. Absent on the first page. A value this API did not issue is 400 `invalid-cursor`.
