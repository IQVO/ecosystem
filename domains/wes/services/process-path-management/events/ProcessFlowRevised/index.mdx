## Description
Raised by DefineProcessFlow when a revision of an ACTIVE flow changes its name or stages, with the full new state and the next version. Also enqueued once per ACTIVE flow at every service start (ADR 0038) with the CURRENT state at the CURRENT version: a consumer that is caught up (it applies a message only when its version is greater than the one it holds) ignores it, a fresh one learns the flow. Keyed by `flow_id`, so one flow's events stay in order on one partition.
