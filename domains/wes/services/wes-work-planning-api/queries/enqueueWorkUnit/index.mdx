## Overview
Adds a releasable unit of work (e.g. a pick task) to a process path's `WorkPool` — the EnqueueWorkUnit use case. `workUnitId` is client-supplied and must be unique within the pool: enqueueing the same `workUnitId` twice returns `409 Conflict` (`work-unit-already-enqueued`) rather than silently creating a duplicate entry — this endpoint is idempotent-by-client-supplied-ID in that sense, though not a pure no-op retry (a second call with the same ID is rejected, not silently accepted). If this is the first unit ever enqueued against the path, a `WorkPool` is auto-provisioned as release-fed with a default WIP limit. Publishes `WorkUnitCreated`.

**Idempotency (ADR-0022).** This resource-creating POST requires a caller-supplied `Idempotency-Key` header. The first request with a given key is processed and its response (status, headers, body — a 4xx included) is stored in the same database transaction as the write; a retry with the same key and the same body replays that stored response verbatim and does not enqueue again. A missing key is `400 idempotency-key-required`; the same key with a different body is `422 idempotency-key-reused`. Use a fresh key per logical action.





## POST `(/paths/{pathId}/work-units)`

### Parameters
- **pathId** (path) (required): The process path's identifier — a named station that owns a queue (unit-in → unit-out), e.g. a pick zone or pack line. Must belong to a process-path family declared in this deployment's process-path catalogue (ADR-0012; today the fleet's sortable-fc topology declares the pick/pack/rebin/slam families, each optionally carrying a "-"-delimited station/zone suffix, e.g. pick-a or pack-station-1). The write endpoints (receiveChargeForecast, commitShiftPlan, enqueueWorkUnit) reject ids outside the declared families with `400 unknown-path-id`; read endpoints surface a missing pool/projection as `404` instead.

- **Idempotency-Key** (header): Caller-supplied key that makes a retried resource-creating POST safe (ADR-0022). **Clients must always send a non-empty key**: a Postgres-backed deployment rejects a missing key with `400 idempotency-key-required` (the in-memory development configuration has no idempotency store and ignores the header). Generate a fresh unique value (e.g. a UUID) per logical action and reuse it only to retry that same request with the same body. Reusing a key with a different body is `422 idempotency-key-reused`.
