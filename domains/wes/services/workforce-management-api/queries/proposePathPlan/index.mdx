## Overview
Computes `heads = ceil(charge / plannedRate)` for one path and raises ShiftPlanProposed for visibility — it persists nothing and commits nothing. A human must still call POST /shift-plans to commit an actual ShiftPlan. This is why the response is 200, not 201: no resource is created. When a high observed idle share (idleness-as-staffing-signal, fed back from labor-performance via `LABOR_PERFORMANCE_MODE=kafka-cache`) is available for this path's task type and exceeds `IDLE_SHARE_TRIM_THRESHOLD` (default 0.30), the computed heads are further trimmed (floored at 1 head minimum) and `trimReason` explains why — fail-open: no idle-share signal available applies no trim.




## POST `(/paths/{pathId}/plan/propose)`

### Parameters
- **pathId** (path) (required): The process path's identity (e.g. "pack", "pick", "stow"). By convention, the Certification required to be assigned to a path has the same name as the PathId.
