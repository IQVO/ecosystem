## Description
Raised when the staffing-gap read model finds that a path's active
`LaborAssignment` count is below the `plannedHeads` committed for it
on the current `ShiftPlan`. This is a **flag, not a decision**: this
bounded context surfaces the gap and never moves anyone in response.
Rebalancing is a human call, recorded back here as a new assignment.

**Site scope (ADR 0034, additive).** When the gap was requested for
one canonical site, `data.site_code` carries it and `active_heads`
counts only associates with an active shift at that site. When
`site_code` is absent the gap is **unscoped** (every site together,
the pre-ADR-0034 behaviour): consumers MUST treat absence as
"unscoped", never as a particular site.

**Not on the integration topic.** Published only to the internal
analytics topic `warehouse.workforce.analytics` (dataschema
`urn:warehouse:workforce-management:analytics:<EventName>:v1`).
