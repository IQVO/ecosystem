## Purpose
Owns the door calendar of every site: every booked time window on every dock door, inbound and outbound, from booking through arrival to door release, the no-double-booking rule, door opening hours and closures, ETA-driven risk and no-shows.

| | |
|---|---|
| Bounded context | `dock-scheduling` |
| Domain | WMS (`wms`) |
| DDD classification | Supporting |
| Tier | WMS |
| Repository | [IQVO/dock-scheduling](https://github.com/IQVO/dock-scheduling) |
| Events | [dock-scheduling](/docs/services/dock-scheduling) |

This service groups the context's synchronous surface: the OLTP REST API (`openapi.yaml`) and, where the
context has one, the separate read-only reports API (`openapi-reports.yaml`) served by its `*-reports`
binary from an isolated analytical database. Endpoints are unauthenticated fleet-wide.


The WMS-tier owner of **door time** in the warehouse-systems platform (ADR 0001, ADR 0002): every booked window on
every dock door, inbound and outbound, from booking through arrival to door release, the no-double-booking rule, door
operating hours and closures, ETA-driven risk and no-shows.

One calendar per door: inbound and outbound appointments share it, and a door whose `dockFlow` is `Both` takes either
direction. Windows are half-open, `[windowStart, windowEnd)`; `[10:00, 12:00)` and `[12:00, 14:00)` are compatible.
Arrival and door release are physical facts owned by yard-management: this API never records them, the service applies
them from yard events (ADR 0003).

Appointment `state` runs `BOOKED -> CHECKED_IN -> COMPLETED`, or `BOOKED/CHECKED_IN -> CANCELLED`, or
`BOOKED -> NO_SHOW`; the last three are terminal. `ETag` is the appointment version; `If-Match` is honoured on the
reschedule and cancel sub-resources (412 on mismatch).

Events are published as CloudEvents on `warehouse.dock-scheduling.events` through a transactional outbox (see
`apis/asyncapi.yaml`, ADR 0004). Every `POST` is idempotent: send an `Idempotency-Key`; a replay carries
`Idempotency-Replayed: true`. Lists are keyset-paged (`limit`, `cursor`) and answer `{items, nextCursor}`. Errors are
RFC 7807 problem documents with `type = https://errors.dock-scheduling.warehouse-systems.dev/<slug>`. There is no
authentication layer (fleet decision 2026-09-11).

The schedule-adherence report (`GET /reports/schedule-adherence`) and the projection freshness are NOT served by this
API: they live on the separate `cmd/reports` binary, specified in `apis/openapi-reports.yaml` (ADR 0006).
