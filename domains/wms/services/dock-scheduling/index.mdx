## Purpose
Owns the door calendar of every site: every booked time window on every dock door, inbound and outbound, from booking through arrival to door release, the no-double-booking rule, door opening hours and closures, ETA-driven risk and no-shows.

Every message is a CloudEvents 1.0 structured-mode JSON document (`application/cloudevents+json`).
`<ctx>.events` topics carry the integration contract; `<ctx>.analytics` topics carry projector input for the
context's own reports and are never consumed by another context.

## Contract


Event catalog for the **dock-scheduling** bounded context (WMS subdomain): the door calendar of every site (ADR 0001, ADR 0002).

**Published.** The `DockAppointment` aggregate raises eight events and the `DockCalendar` aggregate three. Eight of the eleven
go to `warehouse.dock-scheduling.events`; the analytics-only facts (`DockAppointmentCheckedIn`, `DockAppointmentDoorReassigned`,
`DockAppointmentCompleted`, `DockAppointmentAtRisk`, `DoorOperatingHoursDeclared`) go ONLY to `warehouse.dock-scheduling.analytics`.
Every fact is written to its stream through a **transactional outbox**: the aggregate row and its already-encoded events commit in
ONE database transaction and a relay drains them to Kafka (at-least-once; the CloudEvents `id` is stored with the outbox row, so a
retry republishes the same `id`). Kafka key = appointment id (site id for the calendar events), so one appointment's history stays
ordered on one partition.

**Consumed (ADR 0003).** facility-layout (`ZoneRegistered`, `LocationSlotRegistered`, `LocationSlotDecommissioned`),
inbound-receiving (`ASNRegistered`, `ASNCancelled`, and the legacy `DockAppointment*` for the strangler stage A importer),
process-path-management (`CPTScheduleChanged`) and yard-management (`VisitCheckedIn`, `VisitRejected`, `TrailerDocked`,
`TrailerUndocked`). The consumed messages below are restated from the producers' own contracts and never imported.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka header `content-type: application/cloudevents+json;
charset=UTF-8`. `specversion`, `id`, `source` (`/warehouse/dock-scheduling`), `type`, `subject`, `time`, `datacontenttype`
(`application/json`) and `dataschema` (`urn:warehouse:dock-scheduling:events:<EventName>:v1`) are all required. Type =
`com.warehouse.wms.dock-scheduling.<entity>.<EventName>` with entity `dockappointment` or `dockcalendar`. A breaking payload
change is a new `.v2` type, never a mutation.
