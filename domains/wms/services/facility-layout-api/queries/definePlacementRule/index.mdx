## Overview
Defines a PlacementRule: a LocationType, an Effect (Allow or Deny), and a zone predicate matching on zoneCode, temperatureClass and/or hazmat. Every field set on the predicate must match for it to apply (AND semantics); unset fields are wildcards; at least one must be set.

Evaluation at slot-registration time runs in order: any matching Deny rule naming the slot's LocationType rejects it (Deny always wins); if any matching Allow rule exists for the zone at all, the zone becomes an allow-list and the LocationType must be named by one of them; otherwise the zone is unconstrained. The rejection error always names the specific rule violated.

The referenced LocationType must already exist. Publishes PlacementRuleDefined.





## POST `(/placement-rules)`

### Parameters
- **Idempotency-Key** (header): Caller-generated unique key (a UUID per logical submit) that makes a retried request safe (ADR 0019). Clients MUST always send a non-empty, unique-per-submit key: the header is required whenever the service runs with Postgres — i.e. in every deployment — and an absent or empty key is answered 400 `idempotency-key-required`. A replay with the same key and the same body returns the original response verbatim; the same key with a different body is 422 `idempotency-key-reused`. It is declared `required: false` here only because the in-memory development mode (no DATABASE_URL) does not enforce the middleware and the Schemathesis contract run boots that mode.
