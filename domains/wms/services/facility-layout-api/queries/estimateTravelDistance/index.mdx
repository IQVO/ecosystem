## Overview
Computes the shortest travel distance, in metres, between two coded locations over the pure-domain travel graph (ADR-0017): Dijkstra's algorithm honouring one-way aisles and active cross-aisles. The result is flagged `estimated` when any leg of the route used a zone's bay-pitch fallback instead of real aisle centreline geometry.
Same-zone requests route over the zone's travel graph. Cross-zone requests are honoured only when BOTH locations carry recorded position geometry: the answer is the straight-line (beeline) distance between the two positions, always flagged `estimated` because it is a lower bound, not a routed path. When either endpoint lacks geometry the request is refused (422, does not guess) — the travel graph is per-zone, so no honest routed cross-zone path exists yet.
This context reports map TOPOLOGY only: travel TIME, congestion, and route choice under load remain wes-work-planning's concern, never this one's.





## GET `(/distance)`

### Parameters
- **from** (query) (required): The seven-segment LocationCode to travel from.
- **to** (query) (required): The seven-segment LocationCode to travel to.

The outcome of a GET /distance query: the shortest path's total length, whether any leg was estimated rather than measured, and the ordered waypoints traversed (ADR-0017).
