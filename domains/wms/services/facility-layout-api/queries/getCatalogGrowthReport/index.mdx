## Overview
Returns the catalog-growth rows whose day bucket falls in the half-open window [from, to), ordered by day bucket then scope.
Rows are bucketed by the BUSINESS time of the underlying event (its CloudEvents `time`), never by ingestion time, so a replayed or late-projected event lands on the day the change actually happened.
`scope` is the part of the map a change belongs to: a site code for site- and zone-level changes, a zone id for aisle- and slot-level changes, and the empty string for catalog-wide definitions (location types, placement rules, bulk imports).





## GET `(/reports/catalog-growth)`

### Parameters
- **from** (query) (required): Inclusive start of the window, RFC 3339. Compared against each row's day bucket.
- **to** (query) (required): Exclusive end of the window, RFC 3339. A window whose `to` is not after `from` is not rejected; it simply matches no rows.

- **scope** (query): Optional exact-match filter on the row scope (a site code or a zone id). Omit it, or send it empty, for every scope including the catalog-wide one.

- **granularity** (query): Bucket resolution. Only daily buckets are modelled.
