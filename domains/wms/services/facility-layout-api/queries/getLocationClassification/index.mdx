## Overview
Resolves a LocationSlot's LocationCode to its parent Zone (the same Site/Area/Zone/Aisle chain-of-custody resolution `POST /locations` performs) and returns that Zone's `hazmat` and `temperatureClass` attributes. This is a deliberately cheap, denormalized read: it does not return the rest of the LocationSlot or Zone shape, only what a cross-context caller needs to validate placement of a classified product (e.g. `inventory-storage` checking that a Hazmat SKU only lands in a hazmat-rated Zone, or a TemperatureSensitive SKU only lands in a Zone with a matching TemperatureClass) without duplicating Zone data of its own.

This context remains the sole source of truth for these attributes — Zone already carries `Hazmat` and `TemperatureClass`; this endpoint is the concrete realization of this context's Open Host Service / Published Language for that purpose (see ADR-0008).

A code that is not seven `[A-Z0-9]` segments is a 400, not a 404 — it could never identify a slot. An unknown location code, or one whose slot exists but whose zone cannot be resolved, is a 404.





## GET `(/locations/{locationCode}/classification)`

### Parameters
- **locationCode** (path) (required): The slot's full seven-segment code, `SITE-AREA-ZONE-AISLE-BAY-LEVEL-POSITION`.





### Responses

#### <span className="text-green-500">200 OK</span>
The resolved subset of a LocationSlot's parent Zone attributes that a cross-context caller needs to validate placement of a classified product — nothing else about the slot or the zone. Zone remains the source of truth for `hazmat` and `temperatureClass`; this is a denormalized, read-only projection of it, not a new aggregate.
