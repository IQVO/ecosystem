## Overview
The bootstrap mechanism: takes a JSON array of fully-specified rows (a site/area/zone/aisle/bay/level/position address plus a LocationType) and loads a real warehouse's layout in one reproducible call, creating the Site, Zone and Aisle structure on first sight. A row naming structure that already exists reuses it and never mutates it, so an import cannot silently redefine a zone's temperature class.

Validation is **atomic per row** with partial success reported per row: every row is processed, and the report says exactly which rows failed and why. A 500-row export with 3 bad rows still creates the other 497.

This answers 200 OK, not 201: a bulk import is a partial-success report over many rows, not the creation of one addressable resource, so there is no single Location to hand back. Publishes one FacilityLayoutImported carrying the counts, plus the usual per-entity registration events as structure is created.
