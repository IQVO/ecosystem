## Description
Raised by `PUT /sites/{siteCode}/role` through the transactional outbox, once per real change (repeating the current role publishes nothing) (ADR-0037). Kafka key and CloudEvents subject: `siteCode`, so the changes of one site stay ordered. Carries the new and the replaced role. It never implies a transfer-capability change: that is only ever `SiteCapabilityChanged` (ADR-0035). The one-time backfill of migration 0009 publishes no SiteRoleChanged; read the role of existing sites on `GET /sites`.


> **No consumer by design:** Published Language fact; consumed on demand
