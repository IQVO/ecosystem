## Overview
The disposition decision (ADR 0052). RELEASE returns the quantity to usable stock through the same staged-receipt seam as a fresh receipt (it is usable once stowed) and emits `StockReleased`; RETURN_TO_VENDOR and SCRAP remove the unit; REWORK keeps it HELD under a new `reason` (default OTHER). Every decision emits `StockDispositioned`. The decision, the unit's save and the events are one transaction. A unit that already has a final disposition is 409 `held-unit-closed`.

Behind the Idempotency-Key middleware like the other creating POSTs (ADR 0018).




## POST `(/held-stock/{id}/dispositions)`

### Parameters
- **Idempotency-Key** (header) (required): Caller-generated unique key (a UUID per logical submit; a retry reuses it, a new user action mints a new one) that makes a retried request safe (ADR 0018, REST guideline section 2): 1-128 printable ASCII characters. Postgres is the only runtime, so the check is on in every deployment: a missing key is answered with 400 `idempotency-key-required`, a malformed one with 400 `idempotency-key-invalid`; a replay with the same key and the same method, path and body returns the original response plus `Idempotency-Replayed: true`, while the same key with a different method, path or body is 409 `idempotency-key-reused`.

- **id** (path) (required): The held unit's id (`hu-<uuid>`).
