## Description
CONSUMED, not produced (ADR 0035, ADR 0036). Pinned by fulfillment-execution's `apis/asyncapi.yaml`: type `com.warehouse.wes.fulfillment-execution.task.TaskCompleted`, `source=/warehouse/fulfillment-execution`, subject and Kafka key = task id. This service reads only `task_id`, `task_type`, `order_ref`, `line_no` and, on RELOCATE tasks, `sku`, `from_bin`, `to_bin`, `quantity` and `relocation_ref`; every other field (`station_id`, `work_unit_id`, `associate_id`, `duration_seconds`) is ignored. `order_ref` is the additive optional field of ADR 0035 (v1, omitted when empty): the task's order reference, i.e. the OrderId order-management used as `demand_ref`. `line_no` is the additive optional field of ADR 0036 (v1, omitted when unknown): the order line the task was for. A message without `order_ref`, or with any `task_type` other than `PICK` or `RELOCATE`, is a successful no-op; one without `line_no` takes the ADR 0035 counting path. The RELOCATE fields are the additive fields of ADR 0039 (decision E1, v1): fulfillment-execution sends them on RELOCATE tasks only, and a RELOCATE completion is applied as an intra-site move (`StockRelocated`).
