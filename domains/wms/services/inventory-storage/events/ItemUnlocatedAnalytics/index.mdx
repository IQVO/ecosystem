## Description
Raised by the RunCycleCount use case when a count comes up short: the quantity the system believed was in the bin is not there, so the affected StockUnit quantity is flagged Unlocated and removed from usable. This is the explicit escape hatch for the "every item has exactly one known bin" rule.

**Published to both topics** (promoted to the integration topic 2026-10-21, ADR 0043, for exception-management). Subject = stock unit id, Kafka key = SKU on both topics (the split the analytics publisher always used: every fact about one SKU's units stays on one partition while the subject names the lost unit); `data` is byte-identical: `{sku, bin_id, stock_unit_id, quantity}`. Only the `dataschema` stream differs.
