## Description
CONSUMED command, not produced (ADR 0050 — the compensation leg that closes the saga's cancel-after-allocation gap). Pinned by network-inventory-planning's `apis/asyncapi.yaml`: type `com.warehouse.wes.network-inventory-planning.transfer.TransferAllocationReleaseRequested`, `source=/warehouse/network-inventory-planning`, subject and Kafka key = the transfer line id. `data` is exactly seven fields — the whole consumed contract; this service replies with TransferStockAllocationReleased on its own integration topic. Idempotent by transfer_line_id through the `transfer_allocation_releases` ledger: a byte-identical replay returns the original outcome untouched, a conflicting payload is answered with the original outcome and reason IDEMPOTENCY_CONFLICT. A command naming a line this service never decided, or disagreeing with the allocation ledger, is a deterministic refusal — logged and committed past, no event.
