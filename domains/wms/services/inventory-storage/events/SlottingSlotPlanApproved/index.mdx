## Description
CONSUMED, not produced. Pinned by slotting-optimization's `apis/asyncapi.yaml` on develop: type `com.warehouse.wms.slotting-optimization.slotplan.SlotPlanApproved`, `source=/warehouse/slotting-optimization`, subject and Kafka key = the plan id. Only `plan_id`, `site_id`, `approved_at` and `assignments[].{sku, slot}` are read; `moves`, `supersedes_plan_id`, `pick_unit` and `cases_capacity` are ignored. The consumer is consumer-first safe: it only reads what slotting already publishes, so no producer change is required.
