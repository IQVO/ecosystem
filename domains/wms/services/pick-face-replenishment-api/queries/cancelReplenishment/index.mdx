## Overview
Moves a `Requested` request to `Cancelled` with reason `OPERATOR` and
publishes `ReplenishmentCancelled`. Cancelling a request that is already
`Completed` or `Cancelled` is a 409 `replenishment-not-open`. Requires an
`Idempotency-Key`. A request already planned or released as floor work is
not recalled by this service; the downstream work completes or is
cancelled by its own context.





## POST `(/replenishments/{requestId}/cancel)`

### Parameters
- **requestId** (path) (required): The request id (`repl-` followed by a unique suffix, at most 64 characters).
- **Idempotency-Key** (header): Caller-generated unique key (a UUID per logical submit) that makes a
retried request safe. Required whenever the service runs with Postgres,
that is in every deployment, and answered with 400
`idempotency-key-required` when absent; a replay with the same key and
the same body returns the original response, while the same key with a
different body is 422 `idempotency-key-reused`. The in-memory development
mode (no `DATABASE_URL`) does not enforce it, which is why the header is
not marked `required` here.
