## Overview
Raises a request for a SKU of a site outside the periodic detection. The
forward bin is the one the site's latest approved slot plan assigns to the
SKU (422 `no-forward-assignment` when there is none). Without `quantity`
the detector rules size it from the current levels (a request is then
raised only when the pick face is at or below its minimum, otherwise
422 `nothing-to-replenish`; 422 `no-source-stock` when the face is low
but nothing can be moved); with
`quantity` the same invariants apply: at least 1, the projected level plus
the quantity at most the policy maximum (so a policy is required, 422
`no-policy`), at most the source bin's usable stock (422 `no-source-stock`).
At most one request is open per forward bin and SKU (409
`replenishment-already-open`). Publishes `ReplenishmentRequested`. Requires
an `Idempotency-Key`; replaying the same key and body returns the original
request.





## POST `(/replenishments)`

### Parameters
- **Idempotency-Key** (header): Caller-generated unique key (a UUID per logical submit) that makes a
retried request safe. Required whenever the service runs with Postgres,
that is in every deployment, and answered with 400
`idempotency-key-required` when absent; a replay with the same key and
the same body returns the original response, while the same key with a
different body is 422 `idempotency-key-reused`. The in-memory development
mode (no `DATABASE_URL`) does not enforce it, which is why the header is
not marked `required` here.
