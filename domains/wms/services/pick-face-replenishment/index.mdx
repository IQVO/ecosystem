## Contract


Event catalog for the **pick-face-replenishment** bounded context (WMS
subdomain): min/max replenishment of forward pick faces from reserve bins
(ADR 0001, ADR 0002).

**Published.** The `ReplenishmentRequest` aggregate raises three events,
published to `warehouse.pick-face-replenishment.events` through a
**transactional outbox**: the request row and its already-encoded events are
written in ONE database transaction and a relay drains them to Kafka
(at-least-once; the CloudEvents `id` is stored with the outbox row, so a retry
republishes the same `id`). `ReplenishmentRequested` is what wes-work-planning
turns into `REPLENISH` work; `ReplenishmentCompleted` and
`ReplenishmentCancelled` close the request. The same three types are mirrored
on `warehouse.pick-face-replenishment.analytics` (dataschema
`urn:warehouse:pick-face-replenishment:analytics:<EventName>:v1`), together
with `ReplenishmentPolicyDeclared`, which is analytics-only.

**Consumed (ADR 0003).** `BinStockLevelChanged` (pending producer change P1)
and `StockRelocated` from inventory-storage, `SlotPlanApproved` from
slotting-optimization, and `ZoneRegistered`, `LocationSlotRegistered` and
`LocationSlotDecommissioned` from facility-layout. Each feeds a durable local
copy or closes a request (modes `INVENTORY_MODE`, `SLOTTING_MODE`,
`LAYOUT_MODE`, default `permissive`; consumer groups from
`INVENTORY_CONSUMER_GROUP`, `SLOTTING_CONSUMER_GROUP`,
`LAYOUT_CONSUMER_GROUP`). The consumed messages below are the producers' own
contracts, decoded independently here and never imported.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka
header `content-type: application/cloudevents+json; charset=UTF-8`.
Optional W3C trace-context headers (`traceparent`, and `tracestate` /
`baggage` when present) carry the trace of the request that wrote the outbox
row; consumers may extract them, and must not require them.
`specversion`, `id`, `source` (`/warehouse/pick-face-replenishment`), `type`,
`subject` (the request id; `<site_id>/<sku>` for the policy event), `time`,
`datacontenttype` (`application/json`) and `dataschema`
(`urn:warehouse:pick-face-replenishment:<events|analytics>:<EventName>:v1`)
are all required. Kafka key = the subject. Type =
`com.warehouse.wms.pick-face-replenishment.<entity>.<EventName>`. A breaking
payload change is a new `.v2` type, never a mutation.
