## Overview
Records the physical arrival of returned goods. Each line either
matches the RMA (carrying its own `rmaId`, which may differ from the
path's RMA when several RMAs ship in one parcel) or is explicitly
`kind: UNEXPECTED`; there is no silent third state. UNEXPECTED lines
raise `UnexpectedReturnReceived` for exception-management. Moves the
RMA to RECEIVED. Publishes `ReturnReceiptOpened` through the outbox.
Requires an `Idempotency-Key`.





## POST `(/returns/{rmaId}/receipts)`

### Parameters
- **rmaId** (path) (required): The RMA id (`rma-` followed by a unique suffix, at most 64 characters).
- **Idempotency-Key** (header) (required): Caller-generated unique key (a UUID per logical submit) that makes a
retried request safe. The service always runs on Postgres, so it is
required on every deployment and answered with 400
`idempotency-key-required` when absent; a replay with the same key and
the same body returns the original response, while the same key with a
different body is 409 `idempotency-key-reused`.
