## Overview
Creates a NEW Disposition that supersedes the given one, carrying the
original's receipt line, grade and quantity, the operator's `outcome`
and a mandatory `reason` (400 `override-reason-required` when blank).
The original decision is never mutated. A RESTOCK override raises its
own `ReturnLineStaged` (idempotent on its disposition id). Requires an
`Idempotency-Key`.





## POST `(/dispositions/{dispositionId}/override)`

### Parameters
- **dispositionId** (path) (required): The disposition id (`disp-` followed by a unique suffix, at most 64 characters).
- **Idempotency-Key** (header) (required): Caller-generated unique key (a UUID per logical submit) that makes a
retried request safe. The service always runs on Postgres, so it is
required on every deployment and answered with 400
`idempotency-key-required` when absent; a replay with the same key and
the same body returns the original response, while the same key with a
different body is 409 `idempotency-key-reused`.
