## Purpose
Decides which SKUs deserve a forward pick slot: velocity-ranked slot plans and slot moves that a human approves, derived purely from event-fed local copies.

context's own reports and are never consumed by another context.

## Contract


Event catalog for the **slotting-optimization** bounded context (WMS
subdomain): reviewable plans that assign SKUs to forward pick slots, and the
human decision taken on them (ADR 0001, ADR 0002).

**Published.** The `SlotPlan` aggregate raises three events, published to
`warehouse.slotting-optimization.events` through a **transactional outbox**:
the plan row and its already-encoded events are written in ONE database
transaction and a relay drains them to Kafka (at-least-once; the CloudEvents
`id` is stored with the outbox row, so a retry republishes the same `id`).
`SlotPlanApproved` carries the FULL forward assignment map and the moves, so
a consumer needs no lookup; `supersedes_plan_id` names the previously
Approved plan of the site, if any.

**Consumed (ADR 0003).** `SiteSkuDemandChanged` from order-management,
`ProductClassified`, `ProductDimensionsDeclared` and `ProductMeasured` from
product-master, and `ZoneRegistered`, `LocationSlotRegistered` and
`LocationSlotDecommissioned` from facility-layout. Each feeds a durable
local copy (modes `DEMAND_MODE`, `PRODUCT_MODE`, `LAYOUT_MODE`, default
`permissive`; consumer groups from `DEMAND_CONSUMER_GROUP`,
`PRODUCT_CONSUMER_GROUP`, `LAYOUT_CONSUMER_GROUP`). The consumed messages
below are the producers' own contracts, decoded independently here and never
imported.

**Analytics (later phase).** `warehouse.slotting-optimization.analytics` is
reserved for this service's own analytics read side (ADR 0004). Nothing is
published there yet, so it is not declared as a channel.

**Envelope (mandatory).** CloudEvents 1.0, structured content mode, Kafka
header `content-type: application/cloudevents+json; charset=UTF-8`.
Optional W3C trace-context headers (`traceparent`, and `tracestate` /
`baggage` when present) carry the trace of the request that wrote the
outbox row (ADR 0009); consumers may extract them, and must not require
them.
`specversion`, `id`, `source` (`/warehouse/slotting-optimization`), `type`,
`subject` (the plan id), `time`, `datacontenttype` (`application/json`) and
`dataschema` (`urn:warehouse:slotting-optimization:events:<EventName>:v1`)
are all required. Kafka key = the plan id. Type =
`com.warehouse.wms.slotting-optimization.slotplan.<EventName>`. A breaking
payload change is a new `.v2` type, never a mutation.
